# Pillar Checklist Template

各項目を `Yes / No / 要確認` で評価し、`No` を改善バックログ化する。

## 1) 運用上の優秀性 (OPS)
- [ ] ビジネス成果と運用 KPI/SLO を明文化し、定期レビューしている。
- [ ] チームの責任範囲と運用モデル（組織・準備・運用・進化）が定義されている。
- [ ] ログ、メトリクス、トレースを統合し、実用的なアラートに接続している。
- [ ] インフラ、設定、運用手順をコード化し、変更履歴を追跡できる。
- [ ] デプロイは小さく可逆的で、段階リリースとロールバック手順がある。
- [ ] インシデント対応手順（Runbook/Playbook）が最新で訓練されている。
- [ ] 障害注入やゲームデーで運用手順と復旧能力を検証している。
- [ ] マネージドサービス活用で運用負荷と手作業を削減している。

## 2) セキュリティ (SEC)
- [ ] セキュリティ基盤（ガードレール、監査方針、責任分界）が整備されている。
- [ ] IAM は最小権限、職務分離、一時認証情報を原則としている。
- [ ] 監査ログの収集、改ざん防止、検知ルールとアラート運用がある。
- [ ] 多層防御（ネットワーク、計算、アプリケーション）の設計になっている。
- [ ] 保存時/転送時データ保護（暗号化、鍵管理、アクセス制御）が実装されている。
- [ ] 機密データへの直接人手アクセスを最小化し、秘密情報管理を標準化している。
- [ ] 脆弱性管理とパッチ適用、依存関係/設定の継続スキャンを実施している。
- [ ] セキュリティインシデント対応計画を訓練し、復旧と再発防止を回している。

## 3) 信頼性 (REL)
- [ ] ビジネス KPI と可用性目標（SLA/SLO）を定義し監視している。
- [ ] 単一障害点を排除し、要件に応じて冗長化（例: AZ/リージョン）している。
- [ ] 障害分離、非同期化、リトライ、タイムアウト、サーキットブレーカーを設計している。
- [ ] バックアップ、復元、DR（RTO/RPO）の方針があり、定期的に復旧テストしている。
- [ ] 需要変動に合わせた自動スケーリングとクォータ管理を行っている。
- [ ] 変更管理が自動化され、事前検証、段階展開、即時ロールバックが可能である。
- [ ] 既知障害シナリオを定期テストし、結果を設計に反映している。
- [ ] 運用イベントから学習し、再発防止を標準手順に取り込んでいる。

## 4) パフォーマンス効率 (PERF)
- [ ] 性能要件（レイテンシー、スループット、同時実行数）を定量化している。
- [ ] ワークロード特性に合った計算モデル（マネージド/サーバーレス含む）を選択している。
- [ ] データアクセスパターンに基づくストレージ/データベース設計を行っている。
- [ ] ネットワーク経路、キャッシュ、配信設計（CDN 等）を最適化している。
- [ ] 本番相当負荷テストを実施し、ボトルネックを継続的に解消している。
- [ ] パフォーマンス観測データに基づく改善サイクルがある。
- [ ] 新しい高効率技術を比較検証し、採用判断を継続的に行っている。
- [ ] 必要に応じたグローバル配置でユーザー体験を改善している。

## 5) コスト最適化 (COST)
- [ ] クラウド財務管理のオーナーシップ、KPI、定例レビューが確立されている。
- [ ] コスト配賦可能なタグ/アカウント構成で、責任帰属が明確である。
- [ ] 予算、アラート、異常検知によりコスト逸脱を早期検知できる。
- [ ] リソースの適正化（Rightsizing）と購入オプション最適化を実施している。
- [ ] 非本番停止、ライフサイクル管理、未使用資源削除を自動化している。
- [ ] 需要変動に合わせて供給量を制御し、過剰/過小プロビジョニングを避けている。
- [ ] コストとビジネス価値（単位経済性）を紐付けて意思決定している。
- [ ] 継続的最適化のバックログと改善効果測定を運用している。

## 6) 持続可能性 (SUS)
- [ ] 持続可能性 KPI（例: トランザクション当たり資源/影響）を定義している。
- [ ] 影響評価を行い、リージョン選択と設計方針に反映している。
- [ ] アイドル資源削減と高使用率運用で資源効率を最大化している。
- [ ] より効率的なサービス/ハードウェアへの移行を継続評価している。
- [ ] データ保持、削除、アーカイブ方針で不要データ増加を抑制している。
- [ ] ソフトウェア設計で計算量、データ転送量を最小化している。
- [ ] 需要に合わせた供給制御で無駄な処理を抑えている。
- [ ] 組織的な改善サイクル（目標設定、測定、見直し）を回している。
